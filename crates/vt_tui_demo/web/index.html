Token-efficient TUI for vp run

TL;DR

  • While tasks run, vp run shows them as a live tree and hides what they print. At the end it prints the output of tasks that failed or warned.
  • In the first demo below, Codex read 76% fewer tokens than it did with plain output.

How a run looks

  1. The task tree

    Each task is a row showing its state, and its status if the tool reports one.

    The tree doesn't clear the terminal, and it doesn't show what tasks print.

~/acme ❯ vp run verify

  ↑↓ move   ←→ fold   enter output   ctrl-c stop                     brave-otter

  2. A task's output

    Press Enter on a task to see its output.

    Agents don't press keys, so they never see this.

    The tree stays on screen, and the output of failed tasks prints below it.

    Agents can read logs of successful tasks with vp run --last-details if they want.

Try it: lint, build and test

This demo runs vp run verify. The root verify task is vp lint && vp run -r build && vp run -r test. The linter warns, two tasks are cache hits, one test fails, and the builds and tests that pass print long logs. The run starts when you scroll to it.

Things to try

  • Press ↓ to select a row, ← → to fold, Enter to open a task's output.
  • In the output, press Ctrl F and type error, then ↑ for older matches.
  • Drag across the output to select text. It's copied when you let go.
  • When the run is over, type vp run --last-details and the run's name.

Try it: dev servers

vp run -r dev runs until you stop it. Each dev server's row shows its URL once the server is up. tsc --watch doesn't report a status, so its row only says it's running.

Things to try

  • Open @acme/web#dev and type h Enter, as you would in a terminal, to see Vite's shortcuts.
  • Open @acme/ui#dev after about ten seconds. By then tsc has cleared the screen twice, but the earlier output is still there.
  • Type q Enter in a dev server's output. The server exits, and its row shows that it succeeded.
  • In the tree, press Ctrl C to stop the run. Stopped tasks print nothing.

AI agents

An agent reads every byte vp run writes. In agent mode it leaves out colors and key hints, and redraws the tree at most every two seconds.

What Codex sees

Why not print only the final state?

That would cut this run to about 1,100 tokens.

But an agent checking on a run that takes a while would see nothing until it ended, and a run of dev servers doesn't end.

How it works

Task config becomes the tree

// vite.config.ts
tasks: {
  verify: 'vp lint && vp run -r build',
}

// packages/ui/vite.config.ts
tasks: {
  build: ['tsc -b', 'tsdown'],
}

// apps/web/vite.config.ts
tasks: {
  codegen: 'graphql-codegen',
  build: {
    command: 'vp build',
    dependsOn: ['codegen'],
  },
}

After the run

The tree's last frame stays, followed by the output of tasks that failed or warned and a one-line summary.

When the UI is used

The UI hides the output of successful tasks, which is fine only when you can open it. So vp run uses the UI only in a terminal, and only when a run has more than one task.

Details

The task tree

Like a progress bar, the tree is drawn below the cursor. It doesn't clear what's already in your terminal, and it doesn't show task output. When the run ends, its last frame stays in your scrollback.

Icons

○ Waiting for a dependency or a free concurrency slot. The status says which.
⣾ Running. In agent mode the icon is ● and doesn't spin.
◉ Ready: a long-running task, such as a dev server, reported that it's up. The icon turns red or yellow if its status is an error or a warning.
✓ Succeeded. A cache hit has the same icon; its status starts with cache hit.
! Succeeded with a warning. Its output prints after the run.
✗ Failed.
⊘ Cancelled, by Ctrl-C or because another task failed.
– Never started, because the run stopped first.

A group shows its most urgent child: failed first, then running, then waiting, then done.

How the tree fits on screen

  • Rows never move when their state changes, so the selection doesn't jump around.
  • The tree is never taller than the terminal. Groups that finished cleanly fold automatically.
  • If it still doesn't fit, siblings that finished cleanly fold into one N more done row, and the rest scrolls, with ↑ N more and ↓ N more rows at the edges.
  • Nothing is drawn in the first 150 ms, so a run that's over by then, such as one with only cache hits, prints just its summary.
  • No row is highlighted until you press an arrow key, so a run you only watch has no selection.

The task view

Enter on a task opens its output full-screen, like a tmux pane. Colors, wrapped lines and lines that redraw themselves look the way they would in a terminal. A bar at the bottom shows the task, its status and the keys you can press.

Esc Back to the tree
↑ ↓ PgUp PgDn Home Scroll. The bar shows how far back you are.
End Jump to the newest output and keep following it
Typing, Enter Send a line to the task, as in a terminal
Ctrl F Search the output as you type, and use ↑ ↓ to move between matches. A lowercase query matches any case.
Ctrl C Interrupt the task, or stop the run if the task has ended
Ctrl D Close the task's input
Mouse wheel Scroll
Drag Select text. Dragging past the top or bottom scrolls, and letting go copies the text to the clipboard.

When a tool clears the screen, as tsc --watch does, the view keeps the earlier output and adds a screen cleared divider after it.

Typing to a task

Tasks write to a pipe, so tools don't draw spinners or progress bars. The status shows their progress instead.

  • Type in a task's output and press Enter to send the line. Your typing shows at the end of the output, as a terminal would echo it.
  • Ctrl D closes the task's input, and Ctrl C interrupts only that task.
  • Tasks that aren't cached can read what you type. Cached tasks get no input, as today.
  • Prompts that read a line work, and so do Vite's shortcuts (h + enter), which vp dev turns on under the UI.
  • Prompts you answer with arrow keys don't work. Run those tasks on their own, or pass --log=interleaved.
